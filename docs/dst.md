# Deterministic Simulation Testing (DST)

Canban's `canban-sim` crate (`crates/sim/`) runs full-stack, multi-host deterministic simulations of the data layer, SQLite storage fault handling, per-instance dual-write crash failpoints, workflow engine, cross-subsystem scheduler contention, cron schedules, interactive sessions and adoption, review and GitHub PR delivery, drafts, durable event subscriptions, GitHub sync, Herdr observation, notifications, idle reclamation, environment/secret sync, and unified client layer (`canban-client::MultiHostClient`) inside a single-threaded [`turmoil`](https://github.com/tokio-rs/turmoil) simulation stepped deterministically via `sim.step()`.

## Architecture and OS-Boundary Abstractions

The simulation boundary pushes up to `canban-client::MultiHostClient` (the shared client used by Desktop, Mobile, and CLI) running across 1..N real `AppServer` instances backed by real SQLite databases, while intercepting every external OS boundary behind deterministic, seed-driven seams:

1. **Deterministic Network, Stream, Framed Local & Storage Faults (`turmoil` + `TurmoilConnector` + `FaultyStream` + `StorageFaultInjector` + `Failpoints`)**:
   - `turmoil` is strictly confined to `crates/sim` (zero leakage into desktop, mobile, or CLI binaries).
   - Each simulated `AppServer` runs inside a Turmoil host with `ServerRuntimeEnv { inline_workers: true, .. }` so RPC handling, delivery workers, runtime observation, cron schedule evaluation, and GitHub sync execute deterministically inside Turmoil's per-host `current_thread` Tokio runtime without OS background thread pools racing the virtual clock.
   - `MultiHostClient` instances (`"ui-client"` plus optional `extra_clients`) run in their own Turmoil hosts via `MultiHostClient::from_options_with_runtime_id_gen_and_failpoints`, connecting to simulated servers through a `CountingHostConnector` wrapping `FaultyTurmoilConnector` (`HostConnector`) and `FaultyStream` over `turmoil::net::TcpStream` / `TcpListener`.
   - **Framed Local Transport (`SimWorldConfig::framed_local_transport`)**: When enabled, `SimWorld` binds a simulated local framed JSON-RPC listener serving `AppServer::serve_local_stream` over `turmoil::net` and routes `SimLocalHostDriver` RPCs and `app.subscribe` updates through real framed JSON-RPC instead of direct in-process `Arc<AppServer>` calls (`transport.local_framed_rpc`), exercising framed local restart recovery across `bounce_server("local")`. Enabled in Scenario 18 (`scheduler_cross_contention`) and deterministically across half of `chaos` desktop sub-profiles (`AuthMultiClientBlackhole`, `WorkflowAndSchedule`, `FullMix`).
   - **Network & Half-Open Blackhole Faults**: Deterministic link faults (`partition`, `partition_oneway`, `hold`/`release`, `set_fail_rate`, per-link latency/fail rates), `StreamFaultPolicy` byte-stream 1-byte chunking, read/write RST, clean EOF truncation, read/write stalls, and timed bidirectional **half-open blackhole** stalls (`StreamFaultConfig::half_open_blackhole_for_ms` / `arm_half_open_blackhole`) that silently park reads/writes past the 45-second `app.subscribe` keepalive timeout before healing (`chaos.half_open_blackhole`, `chaos.keepalive_timeout_fired`), alongside abrupt `crash_server` (SIGKILL), `stop_server_graceful`, `bounce_server`, `crash_client`, and `bounce_client`.
   - **Per-Instance Dual-Write Crash Failpoints (`canban_types::Failpoints`)**: Scoped per server (`world.failpoints(host)`) and per client (`world.client_failpoints(client)`) — never process-global statics — with zero production overhead (`None` via `Failpoints::check_opt`) and automatic Armed-vs-Fired telemetry mirroring into `CoverageTracker`. Five production dual-write crash windows are instrumented:
     1. `herdr.after_terminal_run_before_db_commit`: right after Herdr `terminal.run` succeeds and before committing the terminal address/run binding to SQLite.
     2. `herdr.after_send_before_db_commit`: right after Herdr `terminal.send` delivers input and before committing `"delivered"` state to SQLite.
     3. `github.after_pr_write_before_db_commit`: right after GitHub `create_pr` or `merge_pr` succeeds remotely and before persisting PR/merge state to SQLite.
     4. `git.after_push_before_batch_finalize`: right after `git push` succeeds on a `sync_upstream: true` merge batch and before finalizing batch/Card state in SQLite.
     5. `outbox.mid_write_truncate`: mid-write torn partial truncation of the client `.outbox.json` file before returning an `io::Error`.
     - **Recovery bugs exposed and fixed by these 5 crash windows**: (1) `runtime.rs` `launch_failed` previously marked uncertain post-`terminal.run` failures `"failed"` directly instead of classifying `LaunchReceiptUncertain` as `"unknown"` so orphan-PTY cleanup closes the leaked terminal instead of relaunching a duplicate agent; (2) `github/delivery.rs` `github.pr.refresh` left stale attention/human gates on `"unknown"`/`"publishing"` PRs and failed to clear `"merge_unknown"` back to live `"open"`/`"closed"` when unmerged; and (3) `runtime.rs` / `merge_batch.rs` left transient `"integrating"`/`"testing"` `merge_batches` rows wedged across restarts and rejected idempotent `batch.report` retries with `DeliveryError::TargetAdvanced` even when the target checkout was already fast-forwarded to `resolved_head`.
   - **SQLite Storage Fault Injection (`StorageFaultInjector`)**: `crates/storage` exposes `StorageFaultInjector` (`StorageFaultKind::Busy` -> `SQLITE_BUSY`, `StorageFaultKind::IoError` -> `SQLITE_IOERR`) armed per host via `world.storage_faults(host)` (`inject_next` / `inject_after_writes`) to verify atomic rollback of business tables and `operations` receipts with zero DB corruption and clean idempotent retries.
   - **Configurable Durability (`FsDurability::NoSync` / `FsDurability::Full`)**: fast runs skip `sync_all()` with `PRAGMA synchronous = OFF` while preserving real SQLite schema/foreign-key semantics, whereas `FsDurability::Full` + `sqlite_synchronous_off = false` (`PRAGMA synchronous = FULL`) verifies real fsync durability in `sessions_and_adoption` and a deterministic 1/8th slice of `chaos` seeds.
2. **Hybrid Instance-Scoped Virtual Clock & Deterministic Entropy (`TurmoilClock`, `IdGen`, Deterministic Vault RNG)**:
   - Turmoil natively drives all `tokio::time` timers (`sleep`, `interval`, `timeout`, `tokio::time::Instant`).
   - Wall-clock epoch timestamps (`created_at`, `updated_at`, `completed_at`, LWW env timestamps, reminder/recovery windows, viewer presence leases, idle reclaim deadlines, and `AgentRun::runtime_status_at`) use an instance-scoped `Arc<dyn canban_types::Clock>` (`TurmoilClock`) with optional per-host clock skew, jumps, and drift, and zero global mutable state.
   - Deterministic ID generation (`IdGenerator` / `IdGen`) ensures repeatable entity creation without host entropy leakage, and `oracle::canonical_state_digest(&world)` produces a UUID-independent state fingerprint across all live hosts.
   - **Deterministic DST Vault RNG**: `crates/storage/src/vault.rs` (`load_or_create_master_key_with_sync_and_id_gen` and `XChaCha20Poly1305` sealing) derives 256-bit master keys and 24-byte `XNonce` values deterministically from the world's `IdGen` in DST (while production defaults to `OsRng`), keeping encrypted vault writes and replays 100% deterministic.
3. **Fail-Closed Subprocess Seam (`SimExec` / `canban_exec::CommandRunner`)**:
   - All CLI probing and subprocess execution inside simulated servers routes through `SimExec` (`crates/sim/src/exec.rs`), seeded with simulated `config/agents.json` profiles using `/bin/echo`.
   - Full in-process `git` fixtures (`SimGitRepo`) back real `crates/workspaces`, `review.*`, `github.pr.*`, and `merge_batch` flows (`worktree add`/`remove`/`list`, `branch`, `checkout`/`switch`, `rev-parse`, `rev-list`, `merge-base`, `merge` including fast-forward, squash, and non-FF merge commits with configurable conflict injection, `cherry-pick`, `rebase`, `diff`, `status`, `symbolic-ref`, `remote`, `fetch`, `push` against simulated upstream refs for `sync_upstream: true` and PR publication, `reset`, `clean`) with real on-disk worktree directories inside isolated `TempDir`s. Deterministic `/bin/sh` handlers serve inline `uses: script` steps (with `CANBAN_ENV`/`CANBAN_OUTPUT` support) and `merge_batch` `test_command` runs, while `ScriptExecutionMode::Herdr` runs real `pump_scripts_herdr()` PTY scripts through `SimHerdr` — all in-process with **zero real OS child processes spawned**. Any unexpected OS binary (`gh`, `ssh`, `hc`, `python3`, `bash`, etc.) fails closed, records `exec.blocked_command`, and is rejected by the `never!` coverage gate.
4. **Transport Auth & External Service Simulators (`SimTailscaleVerifier`, `SimHerdr` & `SimGitHub`)**:
   - **`SimTailscaleVerifier` & `desktop_api_override`** (`crates/sim/src/world.rs`, implementing `canban_transport::TailscalePeerVerifier`): controls per-peer Tailscale WhoIs identity acceptance/rejection (driving real `MultiHostClient` `TAILSCALE_AUTH_SENTINEL` auto-auth, ephemeral `ts_sess_...` token issuance, and automatic `enc:v1:` secret sealing), pairs with `desktop_api_override` for `ApiMismatch` handshake verification, and supports end-to-end `MultiHostClient` pairing/revocation/`AuthFailed` flows alongside raw Turmoil TCP `ClientTransport` helpers.
   - **`SimHerdr`** (`crates/sim/src/herdr.rs`, implementing `canban_herdr::HerdrBackend`): full in-memory Herdr Core simulator with terminal lifecycle, `working`/`idle`/`done`/`blocked` status & turn events, `terminal.read` output/screen buffers, stale/duplicate/dropped/reordered `seq` injection, `missed` snapshot resync, subscriber overflow/disconnects, `set_offline(bool)`, Core identity restarts (`restart_core`), `RunFault` launch failures, `hang_exit`/`hang_kill` timeouts, and recorded `sent_inputs`, `interrupted_terminals`, and `killed_terminals`.
   - **`SimGitHub`** (`crates/sim/src/github.rs`, implementing `canban_github::HttpTransport`): full in-memory GitHub REST API simulator with repos, per-login user IDs, collaborator lists, issues, PR creation/refresh/merge and out-of-band remote merge state, reviews/comments, CI check runs, real `page`/`per_page` pagination with `Link: rel="next"` headers, ETag / HTTP `304 Not Modified`, primary (`403` reset) and secondary (`429` `Retry-After`) rate limits, transient `500`/`409` fault injection, `inject_stale_response_once`, read-after-write lag, per-host offline/IO fault injection, rate-limit budgets, and exact HTTP request counters.

## Universal Invariant Oracle

`InvariantOracle` (`crates/sim/src/oracle.rs`) verifies cross-cutting safety and liveness properties both after every step (`check_step_invariants`) and at quiescence (`check_quiescent_invariants`):

- **Data, Revision & Multi-Entity Durability**: monotonic `Card.revision`, unique entity IDs across all servers and `merged_snapshot()`, `entity_hosts` mapping integrity, bounded snapshot projections, and committed-write durability tracking across server crashes/bounces for Cards, Comments, Global Env entries, `WorkflowRun`s (with monotonic `visit`), persistent `MergeBatch`es (`oracle.committed_merge_batch_checked`), `ScheduledRun`s, and Project `Note`s (`oracle.committed_durability_checked`).
- **Read-Your-Writes & Monotonic Reads (`oracle.read_your_writes_checked`)**: `observe_card_revision` / `observe_write_receipt` records per-`(client, host, card_id)` revision floors from acknowledged RPC write receipts and client snapshots, and `check_read_your_writes(&world)` asserts neither live client `merged_snapshot()` views nor authoritative server snapshots ever regress below an observed/acknowledged floor or silently drop committed Cards.
- **At-Most-Once Idempotency (`oracle.at_most_once_checked`)**: `record_request_key_attempt` / `record_request_key_attempt_with_marker` tracks mutating RPC `request_key` attempts across retries, `SQLITE_BUSY`/`SQLITE_IOERR` rollbacks, failpoint crashes, and server bounces; `check_at_most_once(&world)` inspects SQLite `operations` and `reports` tables plus materialized snapshot/event effects to enforce `<= 1` effect always and `== 1` effect once acknowledged.
- **AuthFailed Zero-Dials Liveness (`oracle.auth_failed_zero_dials_checked`)**: backed by `CountingHostConnector` per-`(client, host)` dial counters (`world.client_dial_count`), `check_auth_failed_zero_dials` / `assert_auth_failed_zero_dials_for` asserts that any remote host in `HostConnectionState::AuthFailed` issues **0** background dial attempts and **0** `reconnect_count` increments across virtual time, background wakes/foreground polls, and rejected routed RPCs until explicitly re-paired.
- **Notifications & Reminders**: monotonic `CardRead.sequence`, exact parity between `snap.reminders` and `reminders_from_events_at(..., server.now_ms())`, zero stale reminders on archived/removed Cards, unique `sound_event_ids`, and non-resurrection across partitions and server restarts.
- **Security & Secret Hygiene**: recursive plaintext secret scanning across server snapshots, timelines, and client `.outbox.json` files on disk (`oracle.outbox_file_scanned`), asserting offline secret saves were actually scanned.
- **Scheduler, Herdr & Workflow Integrity**: `active_count <= max_agents`, Herdr runtime parity, exclusive terminal bindings, `protected_terminals` safety (zero unsolicited input or kills while protected), single active workflow run per Card, and `waiting_approval => human_gate.is_some()`.
- **UI Terminal Invariants**: immediate Project placement on `terminal.create` (`assert_terminal_in_project`) and 4-tier close/exit fallback priority (`same worktree -> same project -> same host -> cross host`, `assert_close_fallback_priority`).
- **Quiescence, SQLite Integrity & Crash Recovery**: unassisted natural convergence (`world.quiesce_natural`), zero remaining `Queued`, `InFlight`, or unexpected `Failed` outbox items (`check_outbox_drained`), full client-to-server convergence across connected hosts (projects, Cards, workflows, terminals, card reads, reminders, global env), `PRAGMA foreign_key_check` + `PRAGMA quick_check` on every SQLite database (`oracle.sqlite_integrity_checked`, plus `oracle.full_durability_checked` under `FsDurability::Full`), and post-bounce startup recovery (`zero AgentRun stuck in "starting"`, `zero Question stuck in "delivering"`, `oracle.post_bounce_recovery_checked`).

## Telemetry, Corpus & Local Deep-Fuzzing

- **Armed vs Fired Fault Telemetry**: `CoverageTracker` records `armed` and `fired` counts for every injected fault (network stream faults, half-open blackholes, storage `Busy`/`IoError`, Herdr/GitHub faults, and all 5 `Failpoints` automatically via `FailpointObserver`) and prints an **Armed vs Fired Faults** table after `--assert-coverage` and `random` runs. Any vacuous fault (`armed > 0 && fired == 0`) **fails `--assert-coverage`**.
- **Cold / Rare Properties Top 10**: Both `run --assert-coverage` and `random` print the 10 lowest-hit recorded properties so under-exercised states remain visible.
- **`never!` Negative Coverage Gate**: `NEVER_COVERAGE_PROPERTIES` enforces `exec.blocked_command == 0` under `--assert-coverage` (and warns on non-asserting `random` runs) so unexpected OS subprocess leaks always fail CI immediately.
- **Regression Corpus (`canban-sim corpus`)**: Permanent failing-seed regressions live in [`crates/sim/corpus/regressions.txt`](../crates/sim/corpus/regressions.txt) (`<scenario> <seed> [ops] # note`) and replay in parallel via `canban-sim corpus --jobs 4 --seed-timeout 60` (also enforced in `.github/workflows/ci.yml` on both macOS and Linux).
- **Scheduled DST Soak & Structured JSON Reports (`--report-json`)**: `run`, `random`, and `corpus` accept an optional `--report-json <path>` flag that writes a structured JSON summary (pass/fail/timeout counts, coverage and Armed-vs-Fired fault telemetry, failure fingerprints, digests, and minimized `--auto-shrink` repro sequences) on both pass and fail. While PR/push CI stays fast with `corpus` + Gate A + Gate B, [`.github/workflows/dst-soak.yml`](../.github/workflows/dst-soak.yml) runs twice weekly (`cron: '0 18 * * 1,4'`, plus `workflow_dispatch`) to execute `corpus`, Gate A, and a bounded 5-minute (`--duration 300 --ops 60 --jobs 4 --assert-coverage --auto-shrink`) chaos soak, uploading failure artifacts and automatically opening an English GitHub Issue via [`scripts/dst-soak-issue.py`](../scripts/dst-soak-issue.py) whenever any phase fails.
- **Local Deep-Fuzz + `--auto-shrink` Workflow**: Extended multi-seed chaos sweeps can also be run locally with `--auto-shrink` to automatically minimize any failing chaos seed within a bounded 32-attempt / 30s budget and append the minimal op sequence to `.local/sim-failures/<scenario>-seed-<N>-ops-<M>.log`.

## Commands & CI Gate

```bash
# Run one complete deterministic simulation round (all 17 scripted scenarios + chaos)
mise run sim

# CI Gate A: full suite with strict property coverage assertions (79 required properties across all 18 scenarios),
# zero vacuous armed faults, `never!` gate (`exec.blocked_command == 0`), and per-seed watchdog timeout
cargo run --release --locked -p canban-sim --bin canban-sim -- run --seeds 1 --assert-coverage --seed-timeout 60

# CI Gate B: parallel Swarm-Testing chaos batch with coverage assertions (34 required base + chaos properties across 12 seeds)
cargo run --release --locked -p canban-sim --bin canban-sim -- random \
  --scenario chaos --seeds 12 --jobs 4 --master-seed 2026 --seed-timeout 60 --assert-coverage

# Replay permanent regression seeds from crates/sim/corpus/regressions.txt (optionally emitting a JSON report)
cargo run --release --locked -p canban-sim --bin canban-sim -- corpus --jobs 4 --seed-timeout 60 --report-json .local/sim-failures/corpus-report.json

# Replay a specific seed / scenario deterministically (with per-scenario coverage gate where defined)
mise run sim -- --seed 202618 --scenario scheduler_cross_contention --assert-coverage
mise run sim -- --seed 202612 --scenario transport_auth --assert-coverage
mise run sim -- --seed 42 --scenario chaos --ops 40

# Replay all previously recorded failing seeds from a failure log index
cargo run --release --locked -p canban-sim --bin canban-sim -- run --replay-file .local/sim-failures/failed-seeds.txt

# Shrink a failing chaos seed down to a minimal reproducing op sequence
cargo run --release --locked -p canban-sim --bin canban-sim -- shrink --seed 42 --ops 40
# Or auto-shrink automatically on failure during `run`:
cargo run --release --locked -p canban-sim --bin canban-sim -- run --scenario chaos --seed 42 --ops 40 --shrink

# Local or scheduled deep-fuzz workflow:
# >=24 chaos seeds also enforce all 6 Swarm sub-profiles (40 required properties total) + bounded --auto-shrink on failures
cargo run --release --locked -p canban-sim --bin canban-sim -- random \
  --scenario chaos --seeds 24 --jobs 4 --ops 50 --master-seed 2028 --seed-timeout 60 --assert-coverage --auto-shrink \
  --report-json .local/sim-failures/soak-report.json

# Continuously run random-seed DST in release mode until Ctrl-C
mise run random-sim

# Run the curated fast DST unit & scenario suite via nextest
mise run test -- -E 'package(canban-sim)'
```

Full-suite runs with `--assert-coverage` (**CI Gate A**: `canban-sim run --seeds 1 --assert-coverage --seed-timeout 60`) enforce **79** required coverage properties across all **18** scenarios (5 base simulation/oracle properties plus 74 suite-level properties covering all 17 scripted scenarios + `chaos`, including Scenario 18's 4-way contention, single-card collisions, mixed PTY reclaim, all 5 dual-write failpoints, natural quiesce, framed local RPCs, Read-Your-Writes, At-Most-Once, AuthFailed zero-dials, and committed merge-batch durability), alongside zero vacuous armed faults and the `never!` negative gate (`exec.blocked_command == 0`). **CI Gate B** (`canban-sim random --scenario chaos --seeds 12 --jobs 4 --master-seed 2026 --seed-timeout 60 --assert-coverage`) enforces **34** required base + chaos coverage properties (covering Desktop/Mobile profiles, framed local RPCs, `FaultyStream` chunk/RST/stall faults, over-keepalive half-open blackholes, 2-client concurrent races, cron schedules, worktree/delivery batches + shell test execution, `SQLITE_BUSY`/`SQLITE_IOERR` rollback, dual-write failpoints, auth revoke/zero-dial/recover, project archive/restore, Read-Your-Writes, At-Most-Once, and natural quiesce recovery); local `>=24`-seed deep-fuzz batches additionally enforce all 6 Swarm sub-profiles (**40** properties total). CI (`.github/workflows/ci.yml`) runs `corpus --jobs 4 --seed-timeout 60`, Gate A, and Gate B in release mode on both macOS and Linux runners, uploading `.local/sim-failures/` artifacts whenever a seed fails or times out. Separately, `.github/workflows/dst-soak.yml` runs twice weekly (`cron: '0 18 * * 1,4'`, plus manual `workflow_dispatch`) on `ubuntu-24.04` to execute `corpus`, Gate A, and a 5-minute (`--duration 300 --ops 60 --jobs 4 --assert-coverage --auto-shrink`) chaos soak with `--report-json` output, uploading failure artifacts (14-day retention) and automatically filing an English GitHub Issue via `scripts/dst-soak-issue.py` on any failure. Every failure writes a non-colliding trace log (`<scenario>-seed-<N>-ops-<M>.log`), appends an exact replay entry to `.local/sim-failures/failed-seeds.txt`, and prints the exact replay command.
